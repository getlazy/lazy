### Read another task’s committed work without exporting

{{taskOperations}} Prefer the SHA when you need an exact version; a branch can advance. In the current repository, read a file with `git show <sha>:<path>`, search with `git grep -n <pattern> <sha> -- <path>`, or compare known commits with `git diff <base-sha>..<sha> -- <path>`. Read-only access to the root checkout does not mean that checkout contains the child’s changes.

Export only when you need to run another commit’s tests or build with writes: create a fresh writable directory under your scratch dir (builders) or a temporary directory (task agents), then `git archive <sha> | tar -x -C <directory>`. Check both commands succeeded before running anything (for a shell pipeline, enable `set -o pipefail`). Run the project’s dependency installation and required generation/setup steps inside the export. An archive contains tracked committed files only: no uncommitted edits, dependencies, generated/ignored files, git metadata or initialized submodules. Tests requiring those need their documented setup; an export failure is not evidence that the child’s code failed. Do not create a worktree, move shared refs or borrow another task’s writable checkout to verify it. An export is for verification, never a way to land a child’s work: use the accept operation above.
